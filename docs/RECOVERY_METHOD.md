# Evidence-backed, whole-program recovery

## Objective

Recover as much source-level structure and behavior as the original Pascal
binary and lawful supporting evidence permit. Liero is the first case, not
a request for another Liero clone. Preserve original routine structure,
calling conventions, layouts and effects where supported. Historical names,
comments and exact source text cannot generally be recovered uniquely.

## The crossword model

### Architectural ownership supports evidence, not new acceptance

The shared archive boundary owns safe file membership, content identity,
sealing and immutable verified reads. Routine tools own the original/host
meaning of records, frozen experiment policy and applicable review. Archive
integrity alone cannot certify behavior, native ABI, source or training labels.
Replay must compare the bytes it validated, not reopen mutable paths after
checking hashes. Historical method compatibility remains a distinct check.

Keep mutable interrupted-run restoration separate from historical evidence
consumption. Reuse existing execution, ledger, contract and export mechanisms;
do not introduce another orchestration framework merely to package them.
Original-binary oracle and routine-specific semantic tests survive the refactor;
only duplicate generic archive seam tests may move to the shared boundary.
See the [completion plan](PROJECT_COMPLETION_PLAN.md) for the bounded migration
and the connected-subsystem finish line.

### Reproducible scoped prototype delivery

A usable assistant may expose a deliberately narrow supported set through
interpretation, original-byte/declared-state checks, deterministic typed lowering
and explicit reviewable export. The model chooses behavioral alternatives; human
facts, interface, vocabulary, checker, renderer and prior measured successes
must remain attributed. No hidden source/body injection or mechanical-source
credit to the model. Validate the original oracle first, select using training
only and evaluate the selected candidate once on terminal.

Runtime presets must pin compatible model/options independently of legacy CLI
defaults. An unsupported-thinking HTTP error is an integration failure, not a
semantic model failure or justification for counting controls. Preserve failed
archives and freeze changes before a new trial. Never reuse terminal failures
for repair. Previously measured corpora demonstrate repeatability, not unseen
generalization or independent support.

Bind exports to exact candidate/source/method/runtime/model/corpus hashes and
replay complete declared-state records. Include raw competing hypotheses,
reviews, assistance and explicit unknowns; export failed trials as failed trials,
never generated stubs. Export or reuse of a complete output must not run
inference or reexecute holdout. Reject partial outputs rather than silently
resuming evaluation. Full private BYOD executable/compiled images are not export
deliverables. Scoped assistant review is not human signoff or whole-routine
acceptance; native type/ABI and caller/reachability gates remain separate.

Caller stack effects are contracts: a callee with RETF2 and6argument bytes can
retain a4-byte far-pointer argument for the next call. Establish those origins
from original bytes/actual relocations and execute compatible composition under
owned nonaliasing bounds; do not substitute incoming register mirrors. Equal
stack widths do not identify historical Pointer versus Longint Pascal types.

### Census triage before bounded execution

Classify the full inventory using original byte extents, real relocations and
current reviewed contracts, not decompiler CALLF text or successful compilation.
Unknown/indirect/alternate entries, external services/FPU and unavailable
file-backed bytes stay explicit blockers. Conservative linear decode is triage
evidence, not exhaustive CFG or code/data proof. Keep mutually recursive
routines as one dependency group; checked callee scopes must fit caller premises
before execution. Source-review reuse alone is not whole-callee resolution.

Separate manual bodies requiring review, genuinely unimplemented leaves and
oracle-ready execution. A leaf remains execution-ineligible until bounded
ABI/memory inputs and an original-byte oracle are frozen. Human-provided typed
interfaces/output constraints must be disclosed. Reuse known slices without
counting them as new discovery. Freeze one small batch and stop expansion under
the existing25percent yield floor; transport/representation failures are
unevaluated candidates with null behavioral recall, not invented0percent
population sensitivity. A failed bounded trial still informs the next distinct
strategy, without silent generated stubs, repeated held-out feedback or lower
source-promotion gates.

### Interpretation before implementation

The packed4141 path applies the same interpretation/check/lowering separation:
model chooses packed start/count/ordering actions, exact-byte checker and original
training memory reject conflicts, and a human typed renderer lowers only a
selected checked interpretation. Report model action discovery separately from
human vocabulary/checker/ABI/Pascal assistance. A supplied positive orchestration
test is not a live recovery. If correct actions fail citation completeness,
record that distinction; the frozen instruction gate still blocks execution.
One authenticated evidence-only completion may amend citations, never actions
or terminal outcomes, and may not become a continuation chain.

The optional48e1 source-trial mode checks model-proposed structured memory
interpretations before requesting Pascal. Freeze alternatives, request budgets
and instruction-citation obligations first. Retain competing hypotheses and
their independent original-training memory checks, instruction conflicts and
counterexamples. The checker is a manually derived scoped specification, not
another learned recovery or an unbiased blind-discovery test.

Distinguish memory agreement from citation completeness: a hypothesis can match
every supplied memory record but fail its declared instruction bindings. Report
both, rather than calling that a semantic failure or silently weakening a frozen
gate. A later citation-policy change requires a separate method snapshot; old
failures remain failures under their original rules. Passing a finite memory
corpus is neither a complete ABI proof nor calibrated correctness probability.
Only the selected checked interpretation assists the next model-generated body;
the existing complete-state source and single-terminal gates remain unchanged.

For an action-compatible, memory-matching hypothesis blocked only by missing
citations, the existing runner supports a separately frozen evidence-only
completion step. Authenticate its original archive and select by training only;
freeze all memory actions and allow only citation fields to change. Supply the
missing citation obligations as explicit assistance. One completion request is
not an independent new recovery and must not become a chain of retries. The
address-presence gate does not validate explanatory prose. Keep the old failed
trial intact, then apply unchanged compilation, complete-state training and
single-terminal checks to the model-generated body. A checked interpretation
does not imply that generated Pascal implements it.

When a checked interpretation fails to lower into compilable, faithful Pascal,
separate understanding from code synthesis. A narrow human-authored typed
emitter can test the interpretation with unchanged complete-state gates rather
than spending another model retry. Disclose mechanical lowering and scaffold
assistance; do not count its source as model output, independent evidence or
weight improvement. Preserve zero-count, overlap and update-order semantics.
No source/training promotion follows merely from finite fixture agreement.

Fine-tuning may address code-synthesis failures, but supervision must match the
failure: directional copies, typed pointer origins, signed zero-count bounds,
copy/update order and instruction-to-source alignment, not unrelated byte
transforms alone. Review corpus provenance and freeze disjoint evaluation before
training. A manually known failing slice can be a development/debugging example,
not an untouched transfer task. Measure executable complete-state recovery,
retention and error rates independently of token loss; keep experimental
weights inactive until applicable evidence gates are met.

An unsolved routine is not an isolated translation problem. Its callers,
callees, shared records and globals constrain its possible meanings. Each
checked solution supplies more constraints on the remaining puzzle:

1. Establish a scoped routine contract from original evidence.
2. Record preconditions, effects, hashes and supporting references.
3. Propagate applicable constraints across evidenced relationships.
4. Detect contradictions and retain unresolved alternatives.
5. Select the next routine or experiment that can remove an important
   ambiguity.
6. Generate, execute and compare candidates; feed counterexamples back into
   the same connected system.

A constructor's checked buffer-capacity field can constrain a refill
routine. A callee's stack cleanup constrains argument interpretation at a
call site; a caller's use of the return value constrains the callee. Shared
field layouts tie otherwise distant routines together.

Use the existing [fact graph](../engine/fact_graph.py), not an unrelated
graph framework. It already distinguishes observed, oracle-verified,
hypothetical, derived, contradicted and unknown facts, supports evidenced
same-value propagation and detects conflicts. That does **not** mean it
already implements a general whole-program constraint solver.

### Reasoning order and repeated passes

Solve tractable pieces first, including supported instruction slices and shared
fields, not only complete routines. Use **deduction** from checked bytes and
contracts before **induction** across independently supported patterns, then
bounded **abduction** where competing explanations remain. Inductive patterns
and abductive hypotheses are not checked premises. Binary-backed checks return
newly established constraints to deduction; stale premises invalidate dependents.

Repeat solve/check/propagate/reconsider passes over the leftovers. A checked
callee or field may unblock a previously deferred piece, whose checked result
can then unblock another. Revisit a failed piece only when a recorded premise
changes or a new discriminating experiment is available; unchanged retries and
duplicate replay are not progress.

Reuse valid manual recoveries as checked premises within their recorded input,
representation and evidence scopes. A stale body must be re-reviewed, but
unresolved native provenance does not invalidate a current scoped source-model
contract. Neither manual acceptance nor supplied-body adapter calibration
demonstrates automated unknown-routine inference. Keep canonical interface
checks and byte-backed output/return obligations enforceable; return named
training-state differences rather than treating memory-only parity as complete
recovery. Supplying obligations is assistance, not proof the model inferred
them. If derivable ABI scaffolding repeatedly consumes failed proposals,
independently check that scaffolding separately from the semantic residual;
disclose the partition and verify the composition without crediting the static
part as learned recovery.

Saturation is relative to current evidence and the supported method: after
reconsidering the remaining frontier, there are no new supported source/facts,
applicable constraint changes or newly actionable pieces. Preserve blockers and
reopening conditions; saturation is not proof of permanent unrecoverability.
Budget exhaustion, low yield, unavailable tools and reaching a milestone are
separate stopping reasons. Retain fixed evaluation budgets and the 25% expansion
floor. The legacy compile-gated improvement loop's idle counter does not
establish source-recovery saturation.

The existing improvement module now provides `run_puzzle_passes`: a bounded
frontier/check adapter for scoped pieces. Each frontier entry supplies a current
premise identity, checked status and explicit blockers. The adapter owning that
frontier must revalidate checks and invalidate status when premises change;
the checker owns fixed candidate budgets and binary-backed validation.
Unchanged failed premises are not retried. Newly changed premises can reopen
pieces on a later pass, including callers unblocked by checked callee contracts.
It reports frontier-settled, evidence-relative saturation, method/environment
blockers, milestone completion, candidate-budget exhaustion and pass-budget
exhaustion separately.
Compilation cannot serve as a checked oracle result.

A substitute peripheral can check instruction semantics without checking the
original device protocol. For example, an owned emulated PIC register can
expose a port-write leaf's ready-path byte/stack effects, but cannot prove a
sound device's busy transitions, reset/read handshake or initialization.
Read back fixture input/output state, restore emulator controls before host
services, and keep the substitute-device label in graph/audit results.
Do not silently enable a different peripheral in a historical frozen probe.

Routine closure and training readiness are different gates. Revalidate actual
target source/shared helpers, not only a separate projection, before claiming
implementation progress. Whole-routine acceptance needs a reviewed accounting
of all paths/ABI/memory/callee/external effects; an exhaustive input projection
can close its declared output domain without proving an unmodeled ABI.
An accepted source body is not automatically a gold corpus pair. Bind its
source/binary/oracle/review identities and record manual or developer-known
bodies. Marked-verified knowledge labels are not revalidated attestations.

When a candidate repeatedly treats numeric DOS offsets as host addresses,
record a representation blocker rather than repairing its semantics by hand
and crediting the model. A high-level signature must resolve pointer/stack
arguments explicitly; numeric register mirrors are observations, not host
addresses. Representation-rejected parsed bodies need hashes/deduplication
just as compiled bodies do. Preserve every model request, including duplicate
repairs, and freeze changed strategies before evaluation. Reuse authenticated
original training traces for already measured seeds; this is not new evidence.
If the changed strategy remains below the yield floor, stop expansion and
state the concrete reopening condition. Disclosed known-source calibration
may address the boundary, but is not unseen-routine recovery or weight gain.

Passing supplied-body calibration must not weaken later recovery gates.
An example-assisted candidate can use valid host pointers yet omit register
mirrors, stack cleanup or the required signature. Compare the full declared
state, not only destination bytes. Bind calibration examples to source/output/
review/runtime/model identities before reuse and preserve the assistance label
in the next freeze. Record memory-only success as a narrower observation, not
as a complete routine or training label. A calibration pass does not itself
authorize larger frontier expansion after another low-yield recovery batch.

Use the existing model-training `--readiness` command to distinguish unique
Pascal pair/project supply from noisy legacy C; it is advisory, read-only and
does not change the existing mixed-corpus trigger or adapter activation.
The threshold is a configured budget heuristic, not evidence of learnability.
The loss-validation project is development data when used for checkpoint/
adapter selection. A separate, frozen project/family-disjoint terminal
behavioral evaluation, equal base/retrieval/adapted budgets and old-project
retention are required before attributing a recovery gain to changed weights.

Candidate compiler/runtime failures belong to the recorded training attempt,
not an infrastructure-shaped success or silent abort. Keep runtime diagnostics
and execution budgets explicit. A selected candidate's held-out failure is
terminal and cannot become another repair request.

Inspect modeled-memory candidates before executing host code: a compiling cast
from a DOS address to a host pointer does not establish a writable allocation.
Freeze that safety gate before evaluation. If an unforeseen unsafe access stops
an existing trial, preserve its proposal/compiler evidence and report the
uncompleted runtime comparison; do not score it as a measured parity result.

Resumption may replay captured model responses, preserving their source hashes
and counting them against the same original request cap. Freeze the prior
response/corpus/model identities, forbid any earlier held-out evaluation, and
reject an attempted request whose outcome is unknown instead of refunding it.
Replayed controls/seeds are integrity checks, not independent evidence.
After low yield, preserve the failed method before changing the strategy; do
not turn known-slice syntax/body repair into a fresh generalization success.

When syntax is the demonstrated blocker, keep model output in a closed typed
sketch vocabulary and render portable Pascal with shared code. Freeze the
schema, renderer, supplied topology and byte-derived semantic constraints
before requesting proposals. Reject contradictory sketches instead of silently
correcting them; retain raw responses and rejected fields under the same request
budget. Reuse training-only selection, source deduplication and one terminal
holdout. Fresh restricted-mode trials cannot resume incompatible source-text
strategies. Replay must bind the recorded sketch to its rendered candidate and
original/Pascal comparisons, not merely observe a compiling baseline.

If deduction already fixes semantics, the model is selecting equivalent syntax,
not recovering an unknown algorithm. A finite passing sketch validates that
mechanism; it must not count toward automatic new-routine yield, source
attestations or weight-learning claims. Supplied signed loop bounds preventing
zero-count underflow are renderer design, not independent model discovery.

An exact-rendering execution gate is useful for closed modeled-memory sketches:
reject any source differing from the validated renderer, and still establish
the harness/input allocation and index bounds. This does not certify arbitrary
Pascal as safe. If a proposal matches the pre-run developer control, reuse its
source-bound compilation/output and label that reuse explicitly. A development
subset withheld from model feedback is not unseen evidence when its control
or developer has already examined the whole corpus.

Composition can extend a checked straight-line prefix through a narrowly
recognized loop without making the generic decoder accept arbitrary branches
or returns. Require exact original instruction/branch bytes, established
pointer bindings and explicit nonaliasing bounds; derive loop limits and
initialization constants from operands. A provably zero entry register can
exclude one branch only when no intervening write changes it. Retain the
unreachable-branch justification and ordered effects in the scoped contract.
Recompute proposal contracts during freeze validation, rather than merely
trusting saved JSON that still references the right binary.

Do not generalize argument layouts beyond the shared decoder's supported
bindings. The 3b22 composition work initially tried alternate slots, which
failed the prefix gate; the implemented shape explicitly retains slots 8/4
and the valid 256-byte initialization window. Extending that gate requires
separate byte/provenance support, not a normalized skeleton or guessed binding.
Developer-authored shape rules on manually known routines and original-memory
regressions validate a mechanism, not unseen recovery or learned abstractions.

Unattended optimization must freeze its candidate neighborhood, ranking and
budgets, not keep requesting guesses until morning. Compare alternatives on
matched training inputs; guard-tagged batch/index identities make seeded stress
payloads distinct, and heldout payloads remain excluded. Remove candidates with
memory/runtime failures, keep their diagnostics and never reinterpret them as
successful baselines. Among candidates passing every measured training check,
source-size/SHA tie-breaks can make selection reproducible, but do not establish
historical fidelity. Select before one terminal holdout, with no alternate
candidate retry after its result. Keep coverage/time/resource stops distinct
from saturation. A supplied loop-flip neighborhood is not neural generalization.

Long-lived experiment processes can die outside Python exception handling.
Do not treat a stale `running` JSON as liveness: retain process-exit evidence
and heartbeat/PID context. Isolate repeated native-tool comparisons in bounded
workers, enable fault diagnostics and let the supervisor publish terminal
failure on crashes/timeouts rather than auto-retrying unknown work.
After interruption, authenticate the frozen method and replay contiguous
completed results, including saved work newer than the last checkpoint.
Incomplete attempts block continuation; replays are not new independent cases.
Debit elapsed work and a conservative in-flight reserve from the original time
budget. Preserve the candidate neighborhood, ranking, coverage/disk limits and
one terminal holdout, with an exclusive continuation claim to prevent concurrent
duplicate evaluation. Retain the failed method/history before lifecycle repair.

When bounded crash diagnostics cannot reproduce a native failure, report the
cause as unresolved. A successful rerun on identical input is diagnostic
evidence, not a replacement for the unknown original attempt. If the frozen
protocol blocks continuation after unknown work, close the experiment incomplete
without forcing selection or a holdout. Reconcile all complete reports against
their frozen sources, corpora and original traces, retaining diagnostic and
unfinished work separately.

Before calling a new routine a transfer experiment, assess whether the frozen
semantic vocabulary actually covers its original bytes. Exact-shape rules
matching only already measured entries expose a method frontier; they do not
establish unseen generalization or whole-program saturation. Mapping boundary,
relocation and non-file-backed entries remain explicit blockers. Extending a
rule after that assessment is development requiring a new freeze, not successful
transfer of the old rule. Millions of equivalent syntax checks cannot substitute
for one new supported contract.

This is not an automatic proof of whole-program fixed point: scope is the
declared frontier, and the adapter must establish dependency compatibility.
The frozen leaf pilot uses this helper for two independently controlled
memory-contract entries. It does not activate them as universally resolved
callees or infer normal-program object identity from isolated COM tests.

Partial Pascal may expose independently testable memory effects while retaining
exact original bytes and unsupported suffixes separately. Such a projection
must not stand in for register/flag/ABI effects, execution of unresolved assembly,
historical source structure or a resolved callee. Keep its source, input-window,
byte-rule and renderer identities replayable; do not install or promote it as a
whole verified routine.

## Competing hypotheses and confidence

When partitioning a model task, replace the full-task output contract rather
than appending conflicting residual instructions. Keep parameter names and
output serialization consistent with the actual inference backend and training
interface. Repair feedback must show the model's residual, not silently supply
a hand-derived wrapper as its prior solution. A corrected prompt is a method
change requiring a new freeze; it does not retrospectively validate old failures.

For each proposed solution, report measured complete-state agreement on the
declared required cases, including numerator/denominator and evaluation split.
Call this fixture contract recall, not a population sensitivity or probability
of routine correctness. Unexecuted candidates abstain rather than score zero.
Unknown paths and conditional dependencies remain separate obligations even
after all finite cases pass. A correctness probability requires an independently
calibrated estimator and representative held-out labels; deterministic related
fixtures do not justify an independence-based confidence interval.
Synthetic compiler-backed training and development-family generation can
demonstrate representation learning within their scope, but cannot establish
original-project recovery or untouched transfer. Keep production adapter
activation separate from explicitly selected experimental inference.

Keep multiple candidate signatures, layouts, targets or behaviors when the
evidence permits them. Each hypothesis needs:

- A stable identity, subject and explicit claim.
- Scope and assumptions, including path/input conditions.
- Supporting and contradicting evidence, with original/source hashes.
- Dependencies on other hypotheses or checked contracts.
- A score with its meaning stated: model ranking is not a calibrated
  probability of correctness.
- A discriminator: what observation or check could reject it.

Test compatible combinations against the already checked parts of the
program. Reject only what the evidence actually contradicts; a missing
trace is not a contradiction. Keep alternatives when tests cannot
distinguish them. Shared dependencies and recursive groups must be checked
together when relevant, rather than choosing an unsupported local guess.

Do not treat mutually supporting guesses as independent evidence. Reusing
one trace through several graph paths must not increase certainty. Model
confidence cannot turn a hypothesis into an observed fact. When support
changes or becomes stale, invalidate affected conclusions and reconsider
the alternatives.

Bound the search. Do not enumerate every combination across the entire
binary. Start with the active connected slice, prune using checked hard
constraints, retain a bounded set of alternatives, and record any
budget-pruned alternatives separately from disproven ones.

## ML/DL's role

Use learned models to propose Pascal bodies, recognize compiler patterns,
rank hypotheses and select useful experiments. Retain validated patterns
for retrieval and, once suitable data and holdouts exist, local training.
Acceptance still needs independently checked binary-backed evidence.

Do not ask a model to rediscover constants or pointer-origin arithmetic that
supported byte transfer rules can establish. Publish those rules' entry
assumptions, exact instruction/relocation support and unknown residue; reject
contradictory proposals without silently editing them into successful ones.
A straight-line prefix cannot certify a later branch or loop: keep those
fields unresolved and let independent execution test proposed behavior.
Changing the method after a known failure is debugging, not an untouched
generalization evaluation. Freeze the method and holdouts before evaluating
new routines; count developer-supplied sketches separately from recovered
behavior and do not infer weight learning from successful repair.

For global-memory effects, distinguish a constant offset from an
object-relative pointer and require established segment provenance.
Unsigned word arithmetic wraps before later shifts; validate the entire
nonwrapping write span against an explicit writable/nonaliasing caller
window. Segment or stack changes must invalidate dependent bindings.
Preserve a frozen failure when adding shared rules afterward, then record
the changed rule identity separately. Guarded original-only execution can
check predicted writes and observed stack balance; it cannot stand in for
Pascal parity, full ABI or normal-program evidence, nor resolve an
unsupported return or justify source promotion.

Two foundational references motivate this design:

- [Recurrent Relational Networks](https://arxiv.org/abs/1711.08028) study
  repeated relational inference on graphs, including supervised Sudoku
  solving. This motivates iterative neighbor updates, not a claim that a
  Sudoku network can decompile Pascal.
- [DreamCoder](https://arxiv.org/abs/2006.08381) combines program search,
  reusable learned symbolic abstractions and neural search guidance. This
  motivates accumulating trusted Pascal/compiler knowledge, not rewriting
  recovered routines into a different design.

These are foundational sources, not a survey of the latest methods. Measure
benefits using fixed tasks, initial evidence and budgets with propagation
enabled versus disabled. Report downstream unlocks, candidate attempts,
counterexamples and new recoveries. More context can help, but improvement
is a measured hypothesis, not a guarantee.

## Acceptance and memory

Keep these evidence levels separate:

| Evidence | What it establishes |
| --- | --- |
| Compilation | Syntax/type compatibility with the actual compiler used |
| Static evidence accounting | Relationship of source to checked original control flow and effects |
| Original-only execution | Behavior observed under the probe's stated conditions |
| Original-versus-Pascal comparison | Matching defined outputs/effects for the recorded contract and cases |
| Normal-program observation | Reached contexts/behavior in an original executable run |

None alone proves universal equivalence. A format test does not certify
unrelated routines. Host FPC execution does not establish TP7 code generation
or real-mode ABI parity. A controlled COM harness does not establish normal
program segment layout.

Persist current contracts and experimental results with hashes and
replayable inputs. Put target-specific discoveries and counterexamples in
the target's reconstruction documentation. General rules belong here;
short operational guardrails belong in [agents.md](../agents.md).

## Lessons established by the current Liero probes

- A compiled baseline, restored skeleton or unchanged proposal cannot count
  as candidate compilation. Capture raw proposals and exact rejection
  reasons; incomplete feedback transport must be observed, not guessed.
- Similarity/CFG normalization and model confidence can rank hypotheses,
  not certify their semantics. A short thunk and lossy decompiler loop
  may describe different entry scopes; inspect the bound bytes first.
- More models/retries are not a remedy for the wrong contract or hypothesis
  space. The constructor's 17 compiled failures could not be repaired by
  copy-loop mutations when initialization constants/offsets were wrong.
  Deriving seven supported fields from bytes removed that ambiguity;
  later name-copy behavior still required independent testing.
- Developer-defined sketches can over-specialize the recovery method.
  That observation does not establish model-weight overfitting. Report
  known-slice repair, untouched-method evaluation and blind-source
  evaluation separately; preserve negative trials when strategy changes.
- Training selects the first passing candidate; the selected candidate gets
  one held-out evaluation and its failure ends the run. Retrying from
  held-out counterexamples turns that set into training. Deduplicate source
  hashes and replay already measured seeds rather than spend the budget
  again. Deliberate mutants test repair machinery, not fresh model success.
- JSON-native evidence records and exact input/rule/source hashes make
  replay meaningful. Formatting can change a rule-file hash without
  changing semantics; keep historical versions distinct rather than
  relabeling snapshots or counting replay as new independent observations.
- The 492c shared-rule repair derived 2966 zero words only under an explicit
  writable/nonaliasing DS window. Three dirty-pattern original runs checked
  the full guarded window and SP balance, but did not execute Pascal or
  establish complete return/flags/register or normal-program contracts.
- A later, separate exact MZ-startup contract closes the static caller gap:
  the initial far call, relocated DS load, near call, clear bytes, minimum
  loader allocation and disjoint active-stack/code/write ranges are checked
  together. Byte facts alone do not prove RAM allocation; the report explicitly
  assumes successful ordinary DOS loading and writable conventional memory.
  Keep this loader-derived path separate from COM observations, unmodified
  normal-program execution and host-Pascal ABI parity. Do not widen a generic
  RET gate when one caller's balanced return can be checked locally.
- In the subsequent instrumented loader-layout comparison, startup's saved ES
  word lies inside the guarded window but outside the clear. Verify that word
  independently against entry PSP/segment observations, verify Pascal did not
  alter those dirty bytes, then disclose the exact two-byte composition.
  Compare the remaining window without normalization. Keep the appended
  dirty-memory bootstrap and post-return collector outside original code,
  active stack and measured memory; inventory every header/continuation patch
  and preserve allocation totals and original relocations. Such a finite
  execution checks the instrumented path, not unmodified program reachability
  or translation of original-only register/stack effects.
- Local training/inference smoke tests prove the adapter path runs.
  Retrieval, constraints, anti-pattern feedback and held-out token-loss
  improvements are not measured binary-backed Pascal recovery gains.
  Continual learning needs qualified cross-project examples and a frozen
  project-level recovery benchmark, not automatic promotion of finite probes.
- Research citations motivate experiments; they are not acceptance evidence.
  Earlier Reddit access failed, so no Reddit-specific finding was established.
  Do not describe foundational papers or previous searches as a fresh survey.
- Original file-routine bytes can execute in a small hash-checked DOSBox
  harness with actual DOS file services. This is narrower than original
  executable startup.
- The string reader retains a four-byte object argument for line skip;
  byte-correct output without correct stack behavior would miss that fact.
- CR at the end of a 128-byte buffer and LF after refill is a meaningful
  boundary case; ordinary short lines do not exercise it.
- The constructor has a 79-byte filename cap and an embedded-NUL stop.
  Checking complete object bytes and dirty initial states also exposes
  unintended zeroing or overwritten object tails.
- Normalize only identified relocated pointer fields, checking their
  expected segment first. Do not mask arbitrary pointer differences.
- Do not transfer a finite harness observation to arbitrary caller addresses
  by assumption. A layout-independent field rule needs its own static or
  broader execution evidence; keep probe preconditions separate from the
  conditions under which that rule can propagate.
- The 1ec2:0000 dword-copy leaf illustrates an inherited-state obligation:
  REP MOVSD has no preceding CLD, so forward copying requires caller DF=0.
  SHR CX,2 truncates the byte count; counts below four write nothing and
  remainders remain untouched. Exact original bytes and finite disjoint-buffer
  comparisons support that scoped contract, not arbitrary DF/aliasing behavior.
  Keep the developer-authored projection of a historically manual slice out
  of unseen-transfer/model-improvement counts, even when its old source was
  not read. Propagate its DF/bounds obligations to an actual caller next.
- The first checked caller passes unsigned 50000 from a PUSH immediate that
  the listing displays as negative. Interpret the operand according to the
  callee's unsigned SHR/REP semantics, not the listing's signed formatting.
  LES binds a pointer-cell origin, not a valid buffer or nonaliasing proof.
  An intervening unreviewed call blocks DF/segment/stack propagation even when
  the local argument setup has no direction-changing opcode. Publish these
  constraints and stop rather than substituting a larger finite test corpus
  for missing caller provenance.
- A correct generated projection is not a test of the target Pascal body.
  Before recording source evidence, compile the actual include and helper
  snapshots against the original trace and fingerprint both. The copy leaf's
  projection and real body now pass the same finite corpus; that closes the
  artifact-binding gap but does not expand the corpus or establish missing
  DF/caller/ABI behavior. Record a partial source review when those obligations
  remain, rather than promoting the whole routine from finite memory checks.
- Complete source review can be supported by a small closed instruction
  partition, rather than requiring arbitrary larger corpora: the signed-word
  leaf's entire byte stream has three closed return cases, one unread argument,
  valid frame-local storage and no globals/callees. The actual source/helper
  maps every case; exhaustive word returns corroborate, not replace, that
  static review. Keep source-level acceptance distinct from host/DOS machine
  ABI, original-program reachability and all-machine-state parity. Never copy
  a sibling's acceptance merely because its listing looks identical.
- When a leaf calls an operating-system service, separate the recovered
  routine from the host service adapter. State which service outcomes are
  implemented and tested; unexpected host errors must abort, not become
  successful-looking DOS results. Original-only caller setup is a fixture,
  not evidence that the caller's Pascal body is recovered.
- Keep leaf and caller effects distinct: Liero's close leaf leaves the handle,
  mode and method slots untouched even after closing the OS resource. Test a
  repeated call and dirty state; do not add a convenient field reset that only
  the caller performs.
- Compose checked neighbors using their actual bodies, not copied summaries
  inside a new candidate. Use labeled synthetic callbacks to challenge a
  dispatcher's error and argument-preservation contract, but never count
  those callbacks as recovered game methods. An unknown resolver is an
  explicit blocker, not a no-op success.
- Test short branches against their exact targets: an empty-name setup branch
  can skip both an OS call and the following store. A prepared register value
  is not evidence that it reaches memory. Record observed emulator error
  mappings as backend-specific instead of replacing them with textbook values.
- A sticky global error is not the current callee's return result. Compose
  wrappers with actual callees and test successful operations after an earlier
  error; preserve return flags separately. An error in close may still permit
  a subsequent setup attempt, so do not impose a new early-exit policy.
- Distinguish shared return tails by exact branch destinations, not visual
  proximity: Liero's read callback backs up SI for CR/1A but not for count
  exhaustion; its skip callback leaves 1A unconsumed. Compare consumed offsets
  and remaining counts alongside output bytes. A continuation token such as
  `3923` is not proof of terminal EOF or of the next callback phase.
- Verify continuation transitions across actual refills, including delimiter
  splitting, rather than replaying each callback only at offset zero. In
  Liero, `390E` switches to `3923` after a trailing CR; refill must preserve
  that new token, count and destination offset. At empty-buffer return,
  callback AX can stay nonzero while ZF is true. Do not equate return flags,
  sticky status and callback identity.
- Wrapper parity must include caller/callee stack effects, not only object
  bytes and return status. When a host language cannot reproduce the original
  ABI, capture the original stack and model retained arguments explicitly,
  with that limitation in the oracle contract.
- Synthetic far callbacks are useful controlled probes for optional methods
  and sticky errors. Validate the exact method slot and receiver address;
  never let a synthetic callback imply that a real method was recovered.

See [Liero reconstruction evidence](../targets/liero/docs/RECONSTRUCTION.md)
for exact scope, commands and current verification limits.

## External prior art and deterministic-first recovery

The [Recomp catalogue](https://recompsoftware.com/projects/) is a discovery
index, not a compatible library or automatically qualified training corpus.
Check the primary project, architecture, compiler, rights and acceptance
definition. A source port or literal static recompilation is not original
Pascal reconstruction.

- [N64Recomp](https://github.com/N64Recomp/N64Recomp) uses symbols/metadata,
  literal instruction-to-C translation and a runtime boundary. Borrow explicit
  boundary/relocation accounting, not an assumed DOS/Pascal backend.
- [Duke2Reconstructed](https://github.com/lethal-guitar/Duke2Reconstructed),
  [Cosmore](https://github.com/smitelli/cosmore) and
  [LEGO Island](https://github.com/isledecomp/isle) illustrate faithful
  reconstruction versus a separate portable fork, historical compiler
  sensitivity and precise comparison scopes. Their reported matching results
  are not reproduced Liero evidence. FPC compatibility is not TP7 byte matching;
  [reccmp](https://github.com/isledecomp/reccmp) is not a 16-bit Pascal tool.
- [DCC's Pascal collector](https://github.com/nemerle/dcc/blob/qt5/tools/makedsig/TPL_PatternCollector.cpp)
  makes runtime recognition worth a bounded check, but documents TP4/5 support
  and uncertain system-unit name mappings. Short wildcard-prefix matches are
  hypotheses, not semantics, full-routine identity or permission to import
  compiler libraries. Require independently checked version/bytes/relocations.
- [SK2Decompile](https://arxiv.org/abs/2509.22114),
  [HELIOS](https://arxiv.org/abs/2601.14598v2) and
  [Context-Guided Decompilation](https://arxiv.org/abs/2511.01763v2) support
  investigating structure-first recovery and contextual guidance. Feed compact
  byte-backed block/callee/effect constraints into the existing engine before
  naming polish or new training. Their benchmark gains do not establish
  16-bit Pascal performance; compilation remains only one gate.
- The distinct [Decompile-Bench](https://arxiv.org/abs/2505.12668) and
  [DecompileBench](https://aclanthology.org/2025.findings-acl.1194/) reinforce
  source/binary alignment, executable evaluation and leakage control.
  Split copied runtime/source families as well as projects; readable
  decompiler output is not verified Pascal supervision.

When deduction fixes a known slice, render it deterministically and spend
zero model requests. Liero's empty-list/default-callback allocator mechanism
recognizes the exact allocator/helper/callback bytes, retains machine-width
arithmetic and separates its controlled host projection from original-only
guards. One complete training comparison gates one terminal validation;
partial traces, changed methods/inputs, altered source and success-shaped
reports without required artifacts cannot become checked evidence.

Integrate a passing slice as a conditional fact, not a whole-routine
attestation. The actual call edge can be known while entry applicability is
unknown: checked COM heap premises do not establish a real caller's DS,
free-list nodes, callback lifetime or error-transfer ABI. The puzzle loop
should remove exactly the discharged prerequisite and retain the other
blockers. Replaying a historical corpus validates integrity, not independence
or learned capability.

Do not add a matcher, graph framework, corpus importer or compiler migration
merely because a reference project has one. Require an active-slice blocker
and reuse existing contracts, facts, runners and training/export machinery.
The [target evidence](../targets/liero/docs/RECONSTRUCTION.md) distinguishes
the measured allocator result, negative/deferred runtime investigation and
remaining obligations.

Applied narrowly to the current cleanup slice: existing fact-graph/audit records
label the original dispatch + synthetic callback as a mechanism, keep real
callback effects/reachability unknown, and retain exact installer/restorer
byte facts separately. This reuses our evidence system, not a second framework.
The static link to a callback target determines the next callee investigation,
not source acceptance. Do not copy their rebuild objective into this project.

Error handling is a dependency graph too: separate caller-address translation
from callback dispatch, cleanup services and termination. A checked prefix
that stops before an indirect transfer does not verify its targets, reentry,
nonreturn contract or actual failure reachability. Preserve unsigned compare,
carry and modulo-subtraction distinctions when rendering Pascal; exclusive
size limits and zero-input bypasses need distinct boundary fixtures. Treat
descriptor/code/data/stack ownership as an explicit contract, not a consequence
of seeing a segment register or a linked-list instruction pattern.

Moving from a fixture to a real caller requires observing the premises at the
call point, not just at startup. Preserve the actual call/return words and
result stores where possible; disclose displaced instructions and prove
collector scratch/payload disjointness. A known frozen Pascal model may be
applied to the observed inputs, but that is a measured-context projection,
not a fresh terminal corpus or model improvement. Record allocation origin
at its precise endpoint separately from later lifetime/aliasing. Decode
error-transfer destinations from original displacements: a jump that skips
an adjacent entry's register clears has a different input contract.

Capture memory is part of the proof obligation. Size original-run batches from
the complete record size and reserved memory regions before evaluation; a
large capture buffer must not overlap target globals, heap, stack or code.
Batching preserves the frozen corpus and terminal budget, not permission for
adaptive cases. For allocator experiments, compare the entire owned heap
window as well as result/global fields: unchanged old headers and overwritten
predecessor/remainder headers are semantic evidence, not merely guard bytes.

Every batch needs a named routine/slice, one blocking question, a measurable
acceptance condition and a stop rule. Prefer existing infrastructure and the
smallest experiment that settles the question. Stop low-yield expansion at
the established hit-rate floor; report actionable residue rather than
relaxing gates or starting another broad framework project.

The [persistent recovery TODOs](RECOVERY_TODO.md) separate completed
measurements from suggested future batches. Resolve the active contract gap,
measure its Pascal counterpart, then freeze the method before widening
coverage. Keep generalizable rules here, operational guardrails in
[agents.md](../agents.md), and exact target counts/hashes in the target docs.
